01

Select three filesystem sources

user, project and local load different settings/instruction locations. The experiment creates safe fixtures in a private project and private SDK config home.

02

Distinguish omission from []

With the pinned TypeScript SDK, omission loads all three sources. [] skips them. A listed subset opts in only to the named sources; the app preserves that distinction in its actual options.

03

Observe loaded instructions

Compare returned project, user and local instruction markers without supplying them in the prompt. The model can Read only data.md, so it cannot fetch the instruction files with a tool. Compliance is an observation, not a complete configuration audit.

04

Compare two hook mechanisms

A trusted command hook from project settings writes a private trace. A programmatic PreToolUse callback guards the data Read and runs even when filesystem sources are [].

05

Know the limits of source filtering

Managed policy, global config, auto memory, authenticated connectors and sandbox credential restrictions have separate behavior. [] alone is not complete isolation.

06

Build explicit classroom configurations

The Alpha and Beta examples use distinct owned cwd, home and config directories, [], disabled auto memory and strict MCP config. Shared-machine directories and hooks are not a production OS or tenant sandbox.
