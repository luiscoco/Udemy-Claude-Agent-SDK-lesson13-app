01

Source locations

project settings/hooks come from cwd/.claude/settings.json. Project CLAUDE.md and rules can load from cwd and parents. user uses the user config area. local includes settings.local.json and CLAUDE.local.md. Parent discovery is described, not separately tested here.

02

Instructions are additive

CLAUDE instruction layers can be additive rather than a strict universal priority ladder. These fixtures use non-conflicting rules. A returned marker demonstrates observed compliance; absence alone is not a complete source-loading diagnosis.

03

Inputs outside settingSources

Managed host/server policy, global ~/.claude.json, auto memory, authenticated claude.ai connectors and sandbox credential restrictions have separate behavior. This app does not remove or bypass any policy.

04

Additional controls

The lab uses a private CLAUDE_CONFIG_DIR and home, disables auto memory, sets strictMcpConfig and disables connector discovery through its environment. No live authenticated connector or managed-policy test is claimed.

05

Extensions and hook types

Skills, commands and subagents can be discovered from selected sources. This lab disables skills and plugins. Only a trusted filesystem command hook and programmatic callbacks execute; HTTP, MCP, prompt and agent hooks are reference types.

06

Version and deployment scope

The pinned TypeScript SDK uses CLI-like omitted defaults. The deck notes older Python versions had different empty-list behavior; no Python SDK is executed here. Real tenant isolation needs its own filesystem/process/container design and policy review; this classroom path factory is not that proof.
